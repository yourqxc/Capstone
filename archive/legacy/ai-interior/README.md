# AI 셀프 인테리어 시각화 — 로컬 파이프라인

방 사진 + 가구 사진 + 놓을 자리를 받아, 그 가구가 그 자리에 놓인 합성 이미지를 만든다.
**모든 처리는 로컬에서 돈다.** Gemini 이미지 편집 API는 비교 기준선으로만 남아 있고 기본값은 호출하지 않는다.

```
방 사진 ─ Depth Anything V2 ─ 바닥 구분·평면 적합 ────────┐
가구 사진 ─ SAM 선택 + RMBG 틈·경계 정리 ─ 누끼 ──────────┤
실제 높이(m) 또는 수동 박스 ─ 크기·배치 ───────────────┴─ 조명·그림자·가림 ─ 합성
```

## 설치와 실행

검증한 환경은 Python 3.13, macOS Apple Silicon(M5 16GB, MPS)이다. CUDA가 있으면 CUDA, 없으면 CPU로 돈다(CPU는 느리다).

```bash
pip install -r requirements.txt
python app.py             # http://127.0.0.1:7860
```

첫 실행 때 모델을 자동으로 받는다. 앱은 Depth Anything V2 Small(95MB)과 SAM ViT-B(358MB), RMBG-1.4(약 177MB), SegFormer B0(약 15MB)를 쓰고,
평가 스크립트는 CLIP ViT-B/32(577MB)를 추가로 쓴다. 이전 환경에서 모델 로드 약 20초, 이후 한 장에 몇 초가 걸렸다.
**AI 다듬기**를 처음 켜면 Stable Diffusion 1.5 인페인팅과 ControlNet 깊이(fp16 약 2.9GB)를 받는다.
이전 실험에서는 한 장에 10초 안팎이 더 걸리고 메모리를 약 7GB 더 썼다. 수정 후 전체 품질 평가는 아직 수행하지 않았다. 기능 회귀 검사와 실제 모델 실행 기록은 DEVLOG §33에 있다.

포트를 고정하려면 `GRADIO_SERVER_PORT=7860 python app.py`. 7860이 사용 중이면 gradio가 다른 포트로 넘어가니
실행 직후 터미널의 `Running on local URL:` 줄을 확인한다.

## 사용법

1. **방 사진**을 올리고 가구를 놓을 자리를 칠한다. 칠한 영역의 아랫변이 가구가 바닥에 닿는 선이다. 자동 모드는 실제 높이로 크기를 계산하고, 수동 모드와 러그는 칠한 영역의 크기를 쓴다.
   칠하지 않으면 아래 슬라이더 좌표를 쓴다.
2. **가구 사진**을 올리고 **가구를 감싸게** 칠한다. 이전 구현의 샘플 10개에서는 칠하지 않으면 4개, 칠하면 8개가 제대로 분리됐다(DEVLOG §19, 수정 후 미재측정).
   하단 **샘플**을 누르면 가구 박스뿐 아니라 참고 높이와 방별 배치 위치도 함께 불러온다. 하단이 잘린 조명 2점은 실패 자료로 보존하고 정상 배치 예제에서는 제외했다.
3. **실제 높이(m)**를 알면 직접 입력한다. 샘플 사진으로 인식된 경우에만 저장된 참고 높이가 적용되며(실측값으로 검증되지 않음), 이름을 같게 적는 것만으로 높이를 추정하지 않는다. 일반 가구 사진은 자동 모드에서 높이를 비우면 오류가 나온다. 높이를 모르면 **수동 (칠한 박스 크기)** 모드를 선택한다.
4. `가구 배치 생성` → Before / 추정한 바닥(초록)·지평선(주황)·배치 위치(빨강) / After.

**가까운 바닥 자리로 위치 보정**은 기본으로 켜져 있다. 가구 밑면과 기존 가구의 점유 영역을 근사해 가까운 빈 바닥으로 옮긴다. 자동·기준 크기는 이동한 거리에 맞춰 다시 계산하고, 수동 크기는 유지한다. 자리가 없으면 원래 위치를 유지하고 처리 내역에 알린다. 정확한 위치를 유지하려면 이 옵션을 끈다. 모든 3D 충돌을 검출하는 기능은 아니다.

**가구 분리 먼저 확인**을 누르면 방 사진이나 치수를 입력하기 전에도 아래 **분리된 가구**에서 누끼를 확인할 수 있다. **분리된 가구 수정**을 펼쳐 원본에 보이는데 빠진 부분을 파랑으로 칠하면 복구되고, 남은 배경을 빨강으로 칠하면 제거된다. 다시 생성하면 반영된다. 원본에서 다른 물체에 가려진 부분은 복구할 수 없다. 배치 안내 그림의 하늘색 외곽은 실제 합성 크기다.

SegFormer 모델은 [NVIDIA 라이선스](https://github.com/NVlabs/SegFormer/blob/master/LICENSE)의 비상업 연구·평가 조건으로 사용하며 가중치는 캐시에서만 읽는다. 고정 버전은 `489d5cd81a0b59fab9b7ea758d3548ebe99677da`이다. 새 라이브러리 설치나 학습은 없다.

**크기·방향·가림 보정**을 펼치면 다음을 직접 조정할 수 있다.

- **기준 물체 (높이 비교):** 방 사진에서 높이를 아는 물체의 바닥부터 꼭대기까지 세로로 칠하고 실제 높이를 입력한다. 기존 카메라 높이 1.4m 가정을 대신한다. 같은 바닥 위의 물체를 기준으로 써야 하며, 거리 차이를 반영할 크기 기준선은 기본 41% 또는 직접 지정값이다. 위아래로 기울여 찍어 수직선이 모이는 사진의 정확한 투시 보정은 아니다.
- **좌우 반전:** 가구가 향하는 좌우를 바꾼다. 글자와 비대칭 구조도 뒤집힌다. 다른 각도에서 본 옆면을 생성하는 기능은 아니다.
- **앞뒤 가림:** 새 가구보다 앞에 남길 물체를 칠한다. 자동 판단이 틀리면 '칠한 영역만'을 선택한다. 이 영역은 그림자와 선택적 AI 다듬기에서도 원본 픽셀로 유지한다. '끔'은 자동·수동 가림을 모두 끈다.
- **조명 강도:** 0~0.6. 0은 가구 원래 색 유지. 유리에 비친 원래 풍경은 이 보정으로 지워지지 않는다.

다른 방을 불러오면 보정 표시가 초기화된다. 같은 방에서 배치 위치만 다시 칠할 때는 유지된다. 가구는 전체와 발끝이 보이고 다른 물체에 가려지지 않은 사진을 사용한다.

5. (선택) **주변 AI 다듬기**를 켜면 합성된 가구 픽셀은 유지하고 주변 배경·그림자만 로컬 Stable Diffusion으로 다시 그린다. 누끼 오류나 가구의 촬영 각도는 고치지 못한다. 가구 자체를 바꾸던 이전 실험과 현재 기본 동작은 다르다(DEVLOG §34).

**가구 틈·경계 정리**는 기본으로 켜져 있다. 새 모델이 선택한 가구의 65% 미만을 남기거나 폭·높이를 10% 넘게 줄이면 보정을 버리고 SAM 결과를 유지한다. 이 검사는 모든 부품 손실을 검출하지는 않으므로, 일부가 지워지면 체크를 끌 수 있다. 실제 적용·거절 여부는 처리 내역에 나온다. SAM 추론은 한 번만 실행해 위험도 확인과 합성에 함께 쓴다.

RMBG-1.4는 [공식 모델 카드](https://huggingface.co/briaai/RMBG-1.4)의 비상업용 조건으로 이 졸업과제에 사용한다. 상업 사용에는 별도 라이선스가 필요하다. 원격 코드와 가중치는 `2ceba5a5efaec153162aedea169f76caf9b46cf8`로 고정했으며 새 라이브러리 설치나 모델 학습은 없다.

처리 내역 창에 판단 근거와 경고가 나온다.

| 경고 | 뜻과 대처 |
|---|---|
| 칠한 영역의 N% 높이만 가구로 잡혔습니다 (확인) | 넉넉히 칠했다면 괜찮다. 가구 일부만 잡혔다면(조명의 갓만 등) SAM 후보를 바꾼다. 크기 계산은 바꾸지 않는다 |
| 배경이 잡혔을 수 있습니다 | SAM이 가구 대신 배경을 잡았다. SAM 후보를 0/1/2로 바꾸거나 가구에 더 딱 맞게 칠한다 |
| 가구 전체가 나온 사진을 사용해 주세요 | 하단이 잘린 조명 샘플이다. 보이지 않는 받침·기둥은 복원할 수 없어 합성을 중단한다 |
| 실제 높이를 입력하거나 수동 모드를 선택해 주세요 | 자동 모드에는 실제 높이(m)가 필요하다. 값을 입력하거나 사용자가 수동 모드를 선택한다 |
| 접지점을 크기 기준선 아래로 옮기세요 | 자동 크기를 계산할 수 없는 위치다. 배치 위치를 옮기거나 수동 모드를 선택한다 |
| 바닥 평면을 찾지 못했습니다 | 세워 놓기는 수동 박스 배치로 진행한다. 바닥에 까는 러그는 오류를 표시하므로 바닥이 더 보이는 사진을 쓴다 |
| 가구가 화면 끝에서 잘렸습니다 / 높이가 N%뿐입니다 | 칠한 영역을 옮기거나 크기 배율을 조정한다 |

가구 사진이 **투명 배경 PNG**(쇼핑몰 제품 컷)면 SAM을 건너뛰고 그 알파를 그대로 쓴다. 누끼 품질은 입력 알파에 달려 있다.

## 파이프라인

| 단계 | 파일 | 하는 일 |
|---|---|---|
| 깊이 | `pipeline/depth.py` | Depth Anything V2 Small, float32 상대 역깊이 (0~1, 클수록 가깝다) |
| 바닥 평면 | `pipeline/geometry.py` `floor_plane` | SegFormer로 바닥·러그를 구분하고 그 영역의 깊이에 평면을 적합한다. 기존 RANSAC 비교는 semantic=False. 크기 기준선 가정은 별도다 |
| 누끼 | `pipeline/segment.py` `cutout` | SAM ViT-B로 객체 선택 후 RMBG-1.4로 틈·경계 보완. 큰 형태 손실 시 SAM 유지. 기존 PNG 알파 보존 |
| 크기 | `geometry.auto_height_px` | `화면 높이 / (접지 y − 지평선 y) = 입력 실제 높이 / 카메라 높이(1.4m 가정)`. 지평선은 사진 높이 41%로 가정한다. 실측 치수 보증이 아니다 |
| 배치 | `geometry.place_transform` | 세우는 가구는 크기와 위치를 맞춘다. 바닥 추정 실패 시 수동 박스 배치가 가능하다. 러그는 바닥 평면으로 사다리꼴을 만들고 크기 배율도 적용한다 |
| 합성 | `pipeline/compose.py` | 축소 시 면적 평균으로 무늬 깨짐 억제, 조명 정합, 접점을 고정한 몸체·발끝 그림자, 깊이 기반 가림, 알파 합성 |
| 다듬기 (선택) | `pipeline/refine.py` | 가구 픽셀을 보호하고 주변만 SD 1.5 + ControlNet 깊이로 다시 그린다. 기본 꺼짐 |

각 파일은 단독 실행된다. 설계 근거와 실패한 시도는 [DEVLOG.md](DEVLOG.md)에 있다.

## 수치 재현

모두 로컬이고 요금이 없다. DEVLOG와 기존 CSV의 값은 이전 구현의 기록이며, 아래 명령은 현재 코드를 실행한다. 09-21 수정 후 품질 수치는 아직 측정하지 않았다.

```bash
python pipeline/geometry.py                          # 바닥 IoU, 기존 튜닝셋 10장
python pipeline/geometry.py samples/holdout/*.png    # 기존 홀드아웃 10장
python eval/run_eval.py --local                      # 로컬 두 조건(가구 자동/칠함) 10쌍, 약 45초
python eval/test_regressions.py                      # 크기·알파·가림·앱 입력·방 분할 회귀 검사 (모델 호출 없음)
python eval/test_harmonize.py                        # 조명 정합 계약 테스트 (중성색 갈변, 색상 유지)
python eval/metrics.py                               # CLIP 지표 자기 검증
python eval/size_check.py                            # 문 높이·카메라 높이를 가정한 크기 대리 평가 (ADE20K 필요)
```

`run_eval --local` 결과는 `eval/results/local-NNN/`에 쌓인다. 수치(`scoresheet.csv`)만 커밋하고 이미지는 다시 만든다.
CLIP 점수는 **같은 방·같은 가구에서 조건끼리 비교할 때만** 의미가 있다. 서로 다른 가구 사이의 품질이나 크기의 사실감은 구별하지 못한다(DEVLOG §23).

기존 문 평가의 `36/62`는 test 90개 중 계산 가능한 62개만 센 조건부 값이다. 문 높이 2.03m·카메라 높이 1.4m는 가정이며 실제 물리 치수 정답이 아니다. 당시 문 단위 분할에서는 같은 방 15장이 dev/test에 중복되어 독립 검증으로 볼 수 없다. 현재 스크립트는 사진 ID로 나눠 `doors_by_room.csv`에 저장한다. 기존 자료를 다시 나눠도 새로운 홀드아웃은 아니며, 현재 프로토콜의 전체 재평가는 아직 수행하지 않았다.

픽셀 완전 일치 비율은 리사이즈·압축에도 달라지므로 방 구조 보존율이나 지각적 품질 점수로 해석하지 않는다. 자연스러움과 실제 제품 동일성은 검증되지 않았다.

## Gemini API 비교 경로 (선택, 유료)

```bash
cp .env.example .env      # API_KEY 입력, REAL_API=1
REAL_API=1 python eval/run_eval.py --yes          # 10쌍 × API 3조건 = 30회, 약 $2
```

- 이미지 모델은 **무료 등급이 없다.** 무료 키로 호출하면 `429 ... limit: 0`이 뜬다. 결제 등록이 필요하고 `gemini-3.1-flash-image`는 장당 $0.067이다.
- 앱에서는 "유료 호출에 동의합니다"를 켜야 Gemini 경로가 실행된다. 상단 배너가 현재 상태(mock/유료)를 보여준다.
- `run_eval`은 `REAL_API=1`인데 `--yes`가 없으면 금액을 알려주고 멈춘다. 결과는 실행마다 `eval/results/real-NNN/`에 따로 쌓인다.
