# 방 사진에 가구를 배치하는 로컬 생성형 시각화

기준일: 2026-10-01

## 프로젝트 목적

사용자가 방 사진과 가구 사진을 올리고 배치 영역을 지정하면, 해당 방에 가구가 놓인 모습을 생성합니다. 결과물의 용도는 인테리어 아이디어를 비교하는 **콘셉트 시각화**입니다. 실제 제품의 세부 형상과 치수, 설치 가능 여부, 물리적인 3D 충돌을 보증하지 않습니다.

이번 개편은 누끼를 원근 변환해 붙이는 기존 방식에서, 여러 참조 이미지를 함께 사용하는 로컬 생성형 편집으로 방향을 바꿉니다. Mac에서 첫 실제 생성의 빨간 안내 박스 잔존을 확인한 뒤 두 참조로 수정했고, 수정 출력에는 안내선이 남지 않았습니다. 동일 입력의 좌·우 배치 요청도 실제 출력으로 확인했습니다. 제품의 형태 변화가 남아 정확한 동일성을 주장하지 않으며, 자연스러움의 개선은 통제 평가 전입니다. 기존 수치와 이미지는 새 모델의 성능 근거로 사용하지 않습니다.

## 성공 기준

| 기준 | 확인 방법 | 현재 판단 |
| --- | --- | --- |
| 방의 시점과 가구의 시점이 어울립니다 | 동일 입력의 이전 방식과 블라인드 비교 | 단일 출력 관찰, 사람 평가 전 |
| 바닥 접지와 그림자가 자연스럽습니다 | 사람 평가와 실패 사례 기록 | 사람 평가 전 |
| 요청한 위치에 가구를 배치합니다 | 목표 박스와 관찰된 가구 영역 비교 | 단일 사례의 좌·우 응답 확인, 정량 평가 전 |
| 편집 영역 밖의 방 픽셀을 유지합니다 | 원본 해상도 PNG의 영역 밖 픽셀 차이 검사 | 단위 검사·실제 출력의 잠금 픽셀 검사 통과 |
| 실패를 재현할 수 있습니다 | 입력, 참조, 프롬프트, 시드, 설정, 로그 저장 | 실행 기록 기능으로 검증 |

## 기존 방식에서 확인한 문제

기존 `archive/legacy/ai-interior/`는 깊이 추정, 바닥 분할, 가구 누끼, 크기 보정, 그림자와 알파 합성을 구현했습니다. 가구 사진에 없는 면을 만들지 못하므로 방과 가구의 촬영 각도가 다르면 배치를 조정해도 어색함이 남습니다. 기존 Stable Diffusion 다듬기는 붙여 넣은 형상을 깊이 조건으로 사용해 이 문제를 해결하지 못한 사례가 있습니다.

근거는 [기존 개발 일지 §21](../archive/legacy/ai-interior/DEVLOG.md#21-알려진-한계-09-18-기준), [§26](../archive/legacy/ai-interior/DEVLOG.md#26-로컬-stable-diffusion으로-다시-그리기--하루-실험)과 `archive/legacy/ai-interior/docs/evidence/14_촬영각도_불일치.png`입니다. 이 기록은 당시 입력과 구현에 대한 관찰이며, 모든 입력에서의 일반적인 실패율을 뜻하지 않습니다.

## 새 처리 구조

1. 방과 가구 이미지를 읽고 방향, 색상 모드와 크기를 정규화합니다.
2. 사용자가 지정한 배치 박스를 0~1 정규화 좌표로 변환합니다. 좌표에 따라 왼쪽·중앙·오른쪽 위치도 자연어로 안내합니다.
3. 기본 참조 이미지는 **깨끗한 방**과 **가구** 두 장입니다. UI의 빨간 배치 미리보기는 기본 모드에서 모델에 보내지 않습니다.
4. 참조의 역할과 목표 좌표를 프롬프트에 적어 `FLUX.2-klein-4B`로 장면 후보를 생성합니다. CLI의 `--guide marker` 또는 `--guide map`에서만 세 번째 위치 안내 참조를 넣어 비교 실험합니다.
5. 원본 방 해상도에서 후처리합니다. 목표 박스를 그림자 여유 영역만큼 확장한 편집 영역 안에 생성 결과를 합성합니다.
6. 페더링은 편집 경계의 **안쪽**에서만 적용합니다. 편집 영역 밖의 픽셀은 원본에서 그대로 복사합니다.
7. 사용자가 앞에 남길 물체를 브러시로 지정했다면 해당 영역도 원본 픽셀로 복원합니다.
8. 무손실 PNG와 입력·설정·프롬프트·실행 로그를 저장합니다.

이 구조는 모델 자체의 인페인팅 마스크 제약과 다릅니다. 모델은 장면 후보를 만들며, 애플리케이션의 합성 후처리가 편집 범위를 제한합니다. 범위를 좁히면 그림자가 잘리거나 경계가 생길 수 있어 여유 영역과 페더 폭을 함께 평가해야 합니다.

초기 설계는 빨간 목표 박스를 표시한 방을 세 번째 참조로 사용했습니다. 첫 실제 생성에서 안내선이 결과에 복제되어 기본 모드를 두 참조로 바꿨습니다. 수정 출력에서 안내선 제거를 관찰했습니다. 참조 추가는 여전히 CLI 비교 실험에 남아 있으며, 좌표와 위치 문구로 위치를 충분히 유도하는지는 더 많은 입력에서 검증합니다.

## 실행 환경

### 우선 환경: Mac M5, 통합 메모리 16GB

Apple Silicon용 MLX 구현인 mflux의 FLUX.2 이미지 편집 CLI를 사용합니다. 우선 설정은 4B 모델, 미리 4비트로 양자화한 커뮤니티 가중치, 작은 출력 해상도와 4스텝입니다. 원본 모델과 커뮤니티 변환본의 구분, 고정 버전과 `--low-ram` 실행 예제는 [모델 실행 근거](MODELS.md)에 있습니다. 첫 실험은 세 참조로 512×352 이미지를 생성했으며 321.749초가 걸렸습니다. 이 시간은 최초 모델 다운로드를 포함합니다. 캐시 사용 두 참조 실행은 12.332초, 좌·우 요청 실행은 각각 13.625초·11.624초였습니다. 기록 구간은 모델 호출과 후처리이며 일반적인 평균 성능이나 순수 GPU 추론 시간으로 해석하지 않습니다. LEFT 실행 로그의 MLX 피크 메모리는 4.25GB로, 전체 프로세스 RSS·시스템 메모리를 뜻하지 않습니다.

### 보조 환경: Colab의 NVIDIA GPU

동일한 4B 모델을 Diffusers의 `Flux2KleinPipeline`으로 실행합니다. CPU offload와 선택적 양자화로 VRAM 사용을 줄이는 경로를 제공합니다. GPU 종류, RAM, 라이브러리 버전과 최종 설정을 기록해야 합니다. Colab은 사용자가 관리하는 런타임에서 모델을 직접 실행하는 환경이며 외부 추론 API 호출 경로와 구분합니다.

최초 설치와 가중치 다운로드에는 인터넷 연결이 필요합니다. 다운로드 후 로컬 실행은 입력 이미지를 외부 추론 서비스로 전송하지 않습니다. 실제 GPU·통합 메모리 여유와 모델 캐시를 확인하기 전에는 최소 사양이나 예상 처리 시간을 확정하지 않습니다.

## 직접 구현하는 부분

- 목표 박스 입력과 좌표 정규화, 참조 이미지 생성, 재현 가능한 프롬프트 구성
- 생성 후보를 원본 좌표계에 되돌리는 후처리와 편집 영역 밖 픽셀 보존
- 브러시로 지정한 전경 물체 보호와 경계 페더링
- 백엔드 선택과 모델 실행 오류·메모리 실패를 드러내는 실행 흐름
- 입력 해시, 시드, 모델·라이브러리 설정과 산출물 기록
- 같은 입력을 사용하는 비교 실험과 실패 유형 분류

사전학습 모델의 가중치를 자체 개발하거나 새로 학습했다고 주장하지 않습니다. 프로젝트의 기여는 배치 제어, 보존 계약, 실행 시스템과 평가에 있습니다.

## 현재 공개 범위

현재 발표 자료에는 사용자 `Sample/` 입력, 이전 방식의 한계, 첫 생성의 품질 실패와 수정 후 실제 출력, 좌·우 배치 비교를 포함합니다. 추가 방·의자 입력의 실제 출력도 진행 문서에 기록했습니다. `outputs/runs/`의 `run.json`에서 실행 성공은 이미지 파일을 생성했다는 뜻입니다. 공개 사례의 `quality_verified=false`를 유지하며 품질 성공으로 보고하지 않습니다. 실행 ID와 관찰 기록은 [진행 기록](PROGRESS.md), 평가 설계는 [평가 계획](EVALUATION.md)을 기준으로 관리합니다.
