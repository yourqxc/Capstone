# 초기 프로젝트 독립 검토와 판정

- 대상: 프로젝트의 변경 전 `ai-interior/`, `presentation/`
- 날짜: 2026-10-01 (Asia/Seoul)
- 방법: `critique` 스킬의 검토 기준과 독립 서브에이전트. 이 환경에는 스킬이 지정한 Opus 도구가 없어 사용 가능한 Codex 검토자로 대체했습니다. 검토자는 신규 구현을 검토하지 않았습니다.
- 보관: 워크스페이스 안에 저장했습니다. 원문에 나온 경로는 이후 `archive/legacy/` 아래로 이동했으며 파일 내용과 줄번호를 보존했습니다.
- 사용자 승인 범위: 단순 리뷰에 그치지 않고 프로젝트 재구성까지 이미 요청하셨으므로, 판정 후 새 메인 코드를 구현했습니다.

## 독립 검토 원문

**7개 발견 사항: 목표를 가로막는 구조 문제 1개, 기능·검증 공백 5개, 요구사항 불일치 1개입니다.** 원본 `ai-interior/`, `presentation/`만 검토했습니다. Mac 우선·Colab GPU 보조는 허용하고 외부 이미지 생성 API는 금지하는 기준입니다. 코드 변경과 API 호출은 하지 않았습니다.

1. **[구조 문제·P1] 자연스러운 시점 변환을 원본 구조로 처리할 수 없습니다.**  
   `ai-interior/pipeline/geometry.py:201–205,227–239`는 침대·의자를 수직 2D 판으로 취급하여 크기와 위치만 바꿉니다. `ai-interior/pipeline/refine.py:90–93,122–123`는 가구 픽셀 전체를 보호하므로 생성 단계에서도 각도, 누락된 면, 원본에 찍힌 명암을 고칠 수 없습니다.  
   **발생 예:** 방은 위에서 내려다본 사진이고 침대는 정면 제품 사진이면, 배치 위치와 그림자가 맞아도 침대의 시점은 그대로 남습니다. 다듬기 강도나 GPU 변경으로 해결되는 문제가 아닙니다.

2. **[공백·P1] 자동 크기는 사진별 카메라 보정 대신 고정 가정을 사용합니다.**  
   `ai-interior/pipeline/geometry.py:66,107–109,308,347–353`은 지평선을 사진 높이의 41%, 카메라 높이를 1.4m로 고정합니다. 깊이에서 구한 별도 지평선은 반환하지만 자동 크기 계산에는 사용하지 않습니다.  
   **발생 예:** 같은 방을 낮은 위치에서 촬영하거나 위쪽을 잘라 업로드하면, 실제 가구 높이를 정확히 입력해도 배치 높이가 달라집니다. 코드의 과거 주석 역시 전체 90개 중 ±25% 범위가 36개였음을 명시합니다(`geometry.py:62–65`).

3. **[공백·P1] 평가 스크립트가 현재 앱의 실제 배치 경로를 평가하지 않습니다.**  
   `ai-interior/eval/run_eval.py:139–157`은 앱의 기본 `floor_placement`, 수동 가림, 크기 기준 보정, 다듬기를 실행하지 않습니다. 샘플을 칠하지 않은 조건도 기본 중앙 박스를 쓰지만, 앱은 샘플별 저장 박스를 선택합니다(`ai-interior/app.py:269–278,331–361`).  
   **발생 예:** 기본 위치 보정으로 겹침이 줄어든 앱 결과와 위치 보정 없는 평가 결과가 서로 다르므로, CSV 점수를 현재 앱의 성능으로 인용할 수 없습니다.

4. **[공백·P1] 자연스러움과 제품 보존을 판정할 검증이 없습니다.**  
   `ai-interior/eval/metrics.py:74–76,97–109`는 가구 종류를 담은 문장과 CLIP 유사도를 비교하고, `eval/run_eval.py:31–34`는 사람 평가와 자연스러움·제품 보존 검증이 없다고 명시합니다. 발표도 수정 후 품질이 미검증이라고 밝힙니다(`presentation/build.js:223,239,272`).  
   **발생 예:** 의자가 더 크게 보이거나 다른 의자로 변해 CLIP 점수가 높아져도, 사용자가 요구한 “이 가구를 자연스럽게 배치”한 결과인지 판정하지 못합니다. 실행 성공이나 높은 픽셀 보존율을 품질 성공으로 삼을 수 없습니다.

5. **[공백·P2] 사용자가 지정한 가구 범위를 일률적으로 안쪽 8%로 줄입니다.**  
   `ai-interior/pipeline/segment.py:60,69–84,150`은 사진 가장자리 가까이에 있는 정확한 박스도 강제로 좁힙니다. 침대 한 장에서 정한 여백 규칙이 모든 입력에 적용됩니다.  
   **발생 예:** 프레임을 꽉 채운 제품 사진의 침대 머리판이나 의자 다리가 가장자리 8% 영역에 있으면, 사용자가 전체 가구를 칠해도 SAM에는 일부를 제외한 프롬프트가 전달됩니다. 결과 마스크가 반드시 잘린다는 뜻은 아니지만 객체 선택의 정확한 입력을 훼손합니다.

6. **[공백·P2] 자동 가림은 입체 가구를 한 깊이의 수직 판으로 판정합니다.**  
   `ai-interior/pipeline/compose.py:259–262,271–278`은 실루엣의 최하단 접점에서 얻은 깊이 하나를 가구 전체에 적용하고, 바닥으로 분류된 픽셀은 가림에서 모두 제외합니다. 침대·소파처럼 앞뒤 길이가 있는 물체의 면별 깊이는 존재하지 않습니다.  
   **발생 예:** 기존 탁자와 새 침대가 교차하는 배치에서 침대 앞부분과 뒤쪽 머리판이 서로 다른 가림 관계를 가져야 해도 같은 기준으로 지우거나 남깁니다. 바닥 자리 탐색 역시 높이 20% 직사각형 근사이므로 이 문제를 검증하지 않습니다(`geometry.py:388–389,409–417`).

7. **[불일치·P1] 원본에는 금지된 외부 이미지 생성 API 실행 경로가 남아 있습니다.**  
   `ai-interior/app.py:390–407,453–456`은 Gemini 선택과 실행을 제공하고, `ai-interior/api_baseline.py:24,99–108`은 `REAL_API=1`에서 방·가구 이미지를 외부 endpoint로 전송합니다. 기본 mock이라는 사실은 외부 호출이 불가능하다는 보장이 아닙니다.  
   **발생 예:** 기존 `.env`에 `REAL_API=1`이 남아 있고 API 옵션을 선택하면 실제 외부 이미지 생성이 실행됩니다. 현재 사용자 제약에서는 이 경로를 정상 기능으로 유지할 수 없습니다.

좋은 점도 확인했습니다.

- 원본은 실패 사례와 과거 수치의 한계를 숨기지 않고 기록하고 있습니다.
- 입력 투명도와 수동 보호 영역을 보존하며, 보정 이미지가 다른 입력에 재사용되는 것도 검사합니다.
- 원본의 로컬 모델 실행 기록이 있으므로, 문제 전체를 M5 16GB의 성능 부족으로 돌릴 근거는 없습니다. 가장 큰 병목은 가구를 고정된 2D 사진으로 취급하는 방식입니다.

메모리는 기존 API 경로의 위치 확인에만 참고했으며, 위 발견 사항은 모두 현재 원본 코드와 문서에서 다시 확인했습니다.

## 판정

| 발견 | 판정 | 직접 확인한 근거와 현재 처리 |
|---|---|---|
| 1. 수직 2D 판과 가구 픽셀 보호 | Worth fixing | geometry.py의 변환 행렬 및 refine.py의 alpha 보호를 직접 읽었습니다. 새 메인은 사진을 조건으로 장면을 다시 생성합니다. |
| 2. 고정 지평선·카메라 높이 | Worth fixing | HORIZON_FRAC=.41, CAM_HEIGHT_M=1.4 및 자동 크기 수식을 확인했습니다. 새 메인은 사용자 이미지 영역으로 크기를 유도하며 실측 치수를 주장하지 않습니다. |
| 3. 앱·평가 실행 경로 차이 | Worth fixing | 앱은 floor_placement와 manual_keep를 쓰지만 run_condition에는 없습니다. 새 앱과 CLI는 workflow.run 하나를 호출하고 평가 파일은 그 실행 기록을 읽습니다. |
| 4. 자연스러움·제품 보존 평가 부재 | Worth fixing | CLIP 비교 문장이 제품 참조의 동일성이나 자연스러움을 판정하지 않음을 확인했습니다. 새 기록은 quality_verified=false를 유지하고 사람 평가 계획과 빈 평가지를 제공합니다. 평가 완료를 주장하지 않습니다. |
| 5. 가구 박스 최소 여백 8% | Worth fixing | clamp_box가 사용자 범위를 8% 여백으로 좁힙니다. SAM이 실제로 가구를 반드시 자른다는 주장은 검토자도 하지 않았습니다. 새 기본 경로는 이 분할 규칙을 사용하지 않습니다. |
| 6. 단일 깊이 자동 가림 | Worth fixing | occluder_mask의 d0 하나 및 바닥 제외를 직접 확인했습니다. 새 모델이 가림을 생성하고 사용자가 전경 픽셀을 명시적으로 보호할 수 있습니다. 모든 3D 가림의 자동 정확성을 주장하지 않습니다. |
| 7. 외부 이미지 API | Worth fixing | app의 Gemini 분기와 requests.post endpoint를 확인했습니다. 현재 실행 코드에는 외부 이미지 API가 없으며 이전 경로는 역사 자료로만 보관합니다. |

검토자가 틀렸다고 판단할 근거는 발견하지 못했습니다. 발견 사항 4와 6은 새로운 생성 모델을 연결하는 것만으로 검증이 끝나지 않습니다. 실제 이미지의 형태·색·위치·가림을 계속 평가해야 합니다. 초기 실험의 안내선 잔존과 제품 색상 변화도 진행 기록에 남겼습니다.
