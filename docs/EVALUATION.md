# 새 가구 시각화 파이프라인 평가 계획

기준일: 2026-10-01. 이 문서는 평가 **계획**입니다. 새 모델의 자연스러움이나 생성 성공률을 측정한 결과표가 아닙니다.

## 무엇을 검증할지

핵심 질문은 같은 방·같은 가구·같은 목표 위치에서 새 방식이 이전 방식보다 자연스럽게 보이는지입니다. 위치 준수, 제품 특징과 원본 방 보존을 함께 확인합니다. 모델 실행 성공과 이미지 품질은 별개로 기록합니다.

## 비교 조건

| 조건 | 입력·동작 | 목적 |
| --- | --- | --- |
| A: 이전 누끼 합성 | 기존 코드의 버전과 설정을 고정하여 재실행 | 기존 방식과 비교 |
| B: 새 생성 후보 | 깨끗한 방·가구 두 참조와 좌표 프롬프트 | 모델이 장면을 어떻게 바꾸는지 관찰 |
| C: 새 최종 합성 | B에 영역 제한, 내부 페더링과 전경 보호 적용 | 사용자가 받는 출력 평가 |
| D: 위치 안내 참조 추가 | 좌표를 유지하고 marker 또는 map 참조 추가 | 추가 참조의 위치 제어와 안내선 잔존 확인 |

우선 사용자 `Sample/` 한 쌍으로 실제 실행과 기록 저장을 확인합니다. 그다음 개발용 6쌍과 튜닝에 사용하지 않을 홀드아웃 6쌍을 준비하는 것을 초기 목표로 둡니다. 숫자는 계획한 표본 수이며 확보·실행한 수가 아닙니다. 방 사진은 분할 전에 식별자로 묶어 같은 방이 개발용과 홀드아웃에 동시에 들어가지 않도록 합니다.

기존 `archive/legacy/ai-interior/samples/`는 이미 튜닝과 시연에 사용한 이력이 있습니다. 이 자료를 새 홀드아웃이라고 부르지 않습니다. 입력의 이용 조건과 출처를 확인하고, 사진 ID·가구 ID·목표 박스·전경 보호 영역을 사례 명세에 저장합니다.

## 통제할 설정

- 같은 사례에서 방·가구·박스·확장 여유와 출력 해상도를 고정합니다.
- 시드는 먼저 42로 고정하고 재시도 여부와 변경 이유를 기록합니다. 실패 결과를 삭제하지 않습니다.
- Mac과 CUDA 결과는 서로 다른 백엔드 실행으로 기록합니다. 같은 시드가 두 백엔드의 동일 픽셀을 보장하지 않습니다.
- 콜드 실행과 가중치가 메모리에 올라온 실행의 시간을 구분합니다.
- 성공한 출력만 선별하지 않고 시도 수, 생성 수, 실패 수를 모두 분모와 함께 보고합니다.

## 자동 검사

| 항목 | 정의 | 판정 |
| --- | --- | --- |
| 편집 영역 밖 변화 픽셀 수 | 원본과 최종 PNG를 같은 해상도의 RGB 배열로 비교 | 0이어야 함 |
| 편집 영역 밖 최대 채널 차이 | 영역 밖 RGB 절대 차이의 최댓값 | 0이어야 함 |
| 전경 보호 영역 변화 픽셀 수 | 브러시 보호 영역의 원본·출력 차이 | 0이어야 함 |
| 출력 규격 | 해상도, 이미지 모드, PNG 저장·재로드 | 원본 좌표계와 일치 |
| 처리 시간 | 준비, 모델 실행, 후처리, 전체를 구분 | 초 단위로 실측 |
| 메모리 | 사용 가능한 시스템 측정과 백엔드 장치 메모리 | 측정 방식과 단위를 기재 |

영역 밖 원본 픽셀 복사는 후처리의 계약입니다. 이를 통과해도 편집 영역 안의 시점, 자연스러움이나 제품 동일성이 검증되는 것은 아닙니다. 원본이 JPEG라면 디코딩한 입력 배열을 비교 기준으로 삼고 결과를 무손실 PNG로 저장합니다. 전체 이미지를 JPEG로 다시 압축한 파일에 픽셀 완전 일치를 주장하지 않습니다.

## 사람 평가

기술을 모르는 평가자가 A와 C를 무작위 좌우 순서로 봅니다. 조건명은 가립니다. 원본 방, 가구 참조와 목표 박스도 함께 제공합니다. 우선 3명 이상을 모집하는 것을 목표로 하며 실제 참여 수를 보고합니다.

| 평가 항목 | 1점 | 3점 | 5점 |
| --- | --- | --- | --- |
| 방 시점과의 일치 | 가구 방향·시점이 크게 어긋남 | 일부 어색함 | 방 원근과 자연스럽게 어울림 |
| 바닥 접지·그림자 | 떠 있거나 그림자가 모순됨 | 접지에 어색함 | 무게감과 빛 방향이 일관됨 |
| 가구 특징 보존 | 가구 종류·주요 형태가 달라짐 | 일부 주요 특징이 바뀜 | 색·재질·주요 구조가 참조와 비슷함 |
| 배치 위치 준수 | 요청 영역에서 크게 벗어남 | 일부 벗어나거나 크기가 어색함 | 요청 영역에 적절히 배치됨 |
| 경계와 가림 | 경계가 보이거나 앞뒤 관계가 틀림 | 일부 부자연스러움 | 주변과 경계·가림이 자연스러움 |

추가로 전체 자연스러움의 선호 조건(A/C/차이 없음)을 받습니다. 사례별 점수와 평가자 간 차이를 남기고 중앙값·범위와 선호 수를 제시합니다. 작은 표본의 결과를 일반 사용자 전체에 대한 성능으로 확대하지 않습니다.

제품 특징 보존은 지각적 유사성 평가입니다. 실제 상품 식별자, 보이지 않는 뒷면, 재질 성분, 실측 치수의 정확성을 검증하는 지표가 아닙니다. CLIP 점수가 필요하다면 동일 사례의 보조 지표로만 사용하고 자연스러움의 대리 정답으로 쓰지 않습니다.

## 실패 유형

각 시도에 다음 원인을 복수로 기록합니다: 모델 다운로드/로드 실패, 메모리 부족, 생성 중단, 가구 누락·중복, 박스 위치 이탈, 빨간 안내 표시 잔존, 제품 형태 변형, 접지·그림자 불일치, 경계 단절, 전경 가림 오류. 실행 실패와 품질 실패를 구분합니다.

위 표의 관찰은 자동 점수나 블라인드 사람 평가 결과가 아닙니다. 시간은 `run.json`의 `elapsed_seconds`로, 입력 준비·저장 후 시작한 모델 호출과 후처리 구간입니다. 추가 방·의자 사례의 출처는 [samples/SOURCES.md](../samples/SOURCES.md)에 있습니다. 기존 실험에 사용한 방·가구의 재사용이므로 새로운 홀드아웃이라고 부르지 않습니다. 위 표는 공개 사례 목록이며 전체 시도 수·실패 수의 분모는 `evaluate.py`가 내보내는 최신 전체 기록을 사용합니다.

모델 실행과 자동 검사를 통과하면 상태를 `생성·자동 검사 완료`로, 평가자가 검토하면 `사람 평가 완료`로 바꿉니다. 처리 도중에는 `다운로드 중`, `로드 중`, `생성 중`처럼 실제 관찰한 단계만 적습니다. 모의 결과나 픽셀 후처리 단위 검사를 생성 성공 결과로 보고하지 않습니다. 첫 marker 실험처럼 파일 생성은 성공했어도 품질 실패가 있으면 두 상태를 함께 적습니다.

## 실행 기록과 빈 사람 평가지 내보내기

프로젝트 루트에서 다음 명령을 실행합니다. 모델을 호출하지 않습니다.

```bash
.venv/bin/python evaluate.py
```

실행할 때마다 `outputs/evaluation/<UTC시각>/`에 새 폴더를 만들므로 이전에 작성한 점수를 덮어쓰지 않습니다.

- `runtime.csv`: 성공·실패를 포함한 모든 실행의 상태, 설정, 입력 해시, 기록 시간과 잠금 영역 변화 픽셀 수
- `quality_review.csv`: 자연스러움, 특징 보존, 위치, 접지·그림자와 가림을 기록하는 **빈 사람 평가 양식**
- `summary.json`: 시도·생성·실패 수와 사람 평가 미실시 상태

현재 사람 점수는 입력하지 않았습니다. 평가 양식을 만들었다는 사실을 평가 완료나 품질 통과로 보고하지 않습니다. UI 산출물의 후보·최종 PNG와 기록을 함께 보며 작성합니다.

## 발표에 추가할 증거

1. 동일 입력의 이전 출력, 새 생성 후보, 새 최종 출력
2. 모델·백엔드·양자화·해상도·시드와 실행 ID
3. 영역 밖·전경 보호 검사 결과와 실측 처리 시간
4. 성공 사례뿐 아니라 대표 실패 사례
5. 사람 평가 표본 수와 조건별 원자료

진행 현황은 [PROGRESS.md](PROGRESS.md), 시스템 범위는 [PROJECT.md](PROJECT.md)에서 확인합니다.
