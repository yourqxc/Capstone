# 캡스톤 중간 발표 대본

기준일: 2026-10-01. 약 7~9분을 목표로 한 초안입니다. 실제 실험이 추가되면 8·11·12번의 설명을 근거에 맞게 고쳐야 합니다. 발표자·팀 정보는 확인 후 추가합니다.

## 1. 방 사진 기반 가구 시각화

안녕하세요. 방 사진과 가구 사진으로 배치 모습을 만드는 로컬 생성형 시각화 프로젝트를 발표하겠습니다.

사용자가 가구를 놓을 위치를 지정하면, 해당 방에 가구가 놓인 모습을 보여 주는 것이 목표입니다. 오늘은 기존 구현에서 확인한 문제와 새로운 처리 구조, 그리고 첫 실제 생성에서 관찰한 실패를 설명드리겠습니다. 통제된 품질 검증은 아직 진행 전이므로, 성능이 좋아졌다고 결론 내리지 않았습니다.

## 2. 문제와 사용자 입력

가구의 제품 사진을 보더라도 내 방에 놓았을 때의 모습을 예상하기는 어렵습니다. 같은 침대라도 방의 크기와 촬영 위치, 빛 방향에 따라 다르게 보입니다.

화면의 두 사진은 사용자가 제공한 방과 침대 입력입니다. 이 입력을 기준으로 사용자가 지정한 위치에 배치했을 때의 색감과 시점, 바닥 접지감을 함께 살펴볼 수 있는 이미지를 만들고자 합니다. 침대 주변의 체크무늬는 원본 사진에 포함된 배경이며, 투명 알파가 있다고 가정하지 않습니다.

## 3. 성공 기준과 범위

성공 기준은 자연스러움, 위치 준수와 원본 보존입니다. 방의 시점과 가구가 잘 어울리는지, 바닥에 제대로 닿아 보이는지는 사람 평가로 확인합니다. 요청 위치에 배치했는지도 별도로 봅니다.

편집 영역 밖의 방은 원본 픽셀과 완전히 같도록 후처리하고 자동 검사합니다. 다만 픽셀이 보존됐다는 사실만으로 합성 품질이 좋다는 뜻은 아닙니다.

이 시스템의 용도는 인테리어 콘셉트 시각화입니다. 실제 상품의 모든 특징, 정확한 치수나 물리적인 설치 가능성은 보증하지 않습니다.

## 4. 이전 방식의 관찰

기존에는 가구를 누끼로 분리하고 깊이와 바닥 추정을 이용해 크기를 보정했습니다. 조명과 그림자도 직접 합성했습니다.

화면은 이전 구현의 자료입니다. 침대의 위치나 크기를 바꾸더라도 원래 사진에서 보던 각도는 그대로 남습니다. 사진에 없는 면을 기하 변환만으로 만들기 어렵기 때문입니다. 기존 Stable Diffusion 다듬기에서도 잘못된 시점이 깊이 조건에 남은 사례를 확인했습니다.

따라서 이번에는 새로운 시점의 장면을 만들 수 있는 생성형 편집을 검토합니다. 이 그림은 새 모델의 결과가 아니며, 과거 실험 수치도 새 모델의 성능으로 사용하지 않습니다.

## 5. 새 생성 구조

현재 기본 방식에서는 두 장의 참조를 함께 사용합니다. 첫 번째는 깨끗한 방으로, 방의 구조와 촬영 시점, 조명을 알려 줍니다. 두 번째는 배치할 가구입니다. 배치 위치는 0부터 1까지의 정규화 좌표로 프롬프트에 적습니다.

초기에는 빨간 박스를 표시한 방을 세 번째 참조로 넣었습니다. 그러나 첫 출력에 빨간 안내선이 남아 기본 입력에서 제외했습니다. marker와 map을 추가하는 조건은 CLI 비교 실험으로 남겼습니다. 화면의 배치 미리보기는 기본 모드에서 모델에 보내지 않습니다.

모델은 공개 가중치인 FLUX.2-klein-4B를 사용하며, 외부 추론 API 없이 직접 실행합니다.

이 모델의 다중 참조 지원은 공식 문서에서 확인했습니다. 그러나 좌표를 잘 따르는지, 가구 특징을 얼마나 유지하는지는 프로젝트 입력에서 직접 평가해야 합니다.

## 6. 편집 범위 제어

모델은 장면 전체의 후보를 만들 수 있으므로, 최종 출력의 변경 범위는 애플리케이션에서 제한합니다.

목표 박스를 그림자 여유만큼 넓히고, 그 안에만 생성 결과를 합성합니다. 페더링은 경계 안쪽에만 적용하며 영역 밖은 원본 RGB 값을 그대로 복사합니다. 앞에 남길 물체를 브러시로 지정했다면 그 부분도 원본으로 복원합니다.

영역이 너무 좁으면 그림자가 잘리거나 경계가 생길 수 있습니다. 따라서 픽셀 보존 계약과 함께 경계의 자연스러움도 평가합니다. 이 슬라이드의 박스는 영역 설명용 표시이며 생성 결과는 아닙니다.

## 7. 사용 흐름

사용자는 방과 가구 사진을 올리고 위치를 지정합니다. 필요한 경우 앞쪽 물체를 칠해 보호합니다. 그다음 로컬에서 후보를 생성하고 원본과 최종 결과를 비교합니다.

완료된 PNG와 함께 시드, 모델 설정, 프롬프트와 실행 로그를 저장합니다. 메모리 부족이나 생성 중단도 기록합니다. 모델을 로드한 상태와 이미지를 끝까지 생성한 상태를 구분해 표시해야 합니다.

## 8. 실행 환경

우선 환경은 Mac M5와 통합 메모리 16GB입니다. Apple Silicon용 MLX 구현인 mflux에서 4비트 양자화를 사용하고, 작은 해상도로 실제 실행을 확인합니다.

보조 환경은 Colab의 NVIDIA GPU입니다. Diffusers로 동일 모델을 실행하고 CPU offload와 선택적 양자화를 사용합니다. GPU 종류와 VRAM, RAM도 기록합니다.

Mac에서 첫 512×352 생성은 완료했습니다. 최초 다운로드를 포함한 기록은 321.749초였고, 캐시를 사용한 두 참조 실행은 12.332초였습니다. 이는 한 사례의 모델 호출과 후처리 시간입니다. 순수 GPU 추론이나 평균 성능으로 설명하지 않습니다.

왼쪽 배치 실험의 MLX 피크 메모리는 4.25GB였으며 전체 프로세스나 시스템 메모리 사용량을 뜻하지 않습니다. CUDA는 실제 생성 전입니다. Colab은 해당 런타임에서 모델을 직접 실행하는 경로입니다.

## 9. 직접 구현하는 기여

사전학습 모델은 공개 모델을 활용합니다. 모델 가중치를 자체 개발했다고 설명하지 않습니다.

직접 구현하는 부분은 사용자 박스와 참조 이미지, 프롬프트를 연결하는 배치 제어입니다. 또한 원본 픽셀을 보존하는 후처리와 전경 보호, 백엔드 실행과 오류 표시, 재현 가능한 기록 저장을 담당합니다.

같은 입력을 사용하는 평가와 실패 분석까지 포함해, 모델을 배치 시각화 문제에 적용하는 시스템을 구성합니다.

## 10. 평가 설계

같은 방, 같은 가구와 같은 위치로 이전 누끼 합성, 두 참조의 새 생성 후보, 최종 보존 합성을 비교합니다. 위치 안내 참조를 추가하는 조건도 만들어 위치 제어와 안내선 잔존을 확인합니다.

프로그램은 영역 밖과 보호 영역의 변화 픽셀 수가 0인지 검사합니다. 시간과 메모리는 실제로 측정합니다. 평가자는 조건 이름을 모르는 상태에서 시점, 접지, 가구 특징, 위치와 경계·가림을 봅니다.

우선 Sample 한 쌍의 실제 실행을 확인합니다. 이후 개발용 6쌍과 홀드아웃 6쌍, 평가자 3명 이상을 목표로 합니다. 이 숫자는 아직 확보한 결과가 아닌 평가 계획입니다. 기존 튜닝 사례를 새로운 홀드아웃으로 부르지 않습니다.

## 11. 실패 관찰과 수정 결과

왼쪽은 최초 세 참조 실험의 실제 출력입니다. 방에 맞는 침대의 시점이 만들어졌지만, 빨간 안내 박스가 남았고 침대와 침구의 색·형태가 참조와 달라졌습니다.

오른쪽은 기본 입력과 지시문을 수정한 두 참조의 실제 출력입니다. 빨간 안내선은 사라졌습니다. 다만 보랏빛 침구와 헤드보드·베이스 형태 변화는 남아 제품 동일성이 검증됐다고 설명하지 않습니다.

두 결과 모두 이미지 생성과 잠금 영역 원본 일치 검사를 통과했습니다. 파일 생성 완료와 품질 성공은 다른 판단입니다. 실행 기록의 품질 검증 상태도 false입니다. 최초의 다운로드 포함 시간과 캐시 실행 시간을 순수 추론 속도 향상으로 비교하지 않습니다.

핵심 단위 검사 6개와 앱 실행을 확인했습니다. 단위 검사는 모델을 호출하지 않습니다. 자연스러움의 사람 평가와 CUDA 실행은 아직 실시하지 않았습니다.

실행 ID와 설정은 각 슬라이드의 발표 메모와 진행 문서에 남겼습니다. 단일 사례의 관찰과 통제된 품질 평가 결과를 구분합니다.

## 12. 위치 응답과 다음 검증

같은 방과 가구, 같은 설명, 시드42와 512×352 해상도에서 목표 박스를 왼쪽과 오른쪽으로 바꿨습니다. 그에 따라 위치 프롬프트와 편집 마스크도 바뀝니다. 화면에서 두 방향으로의 배치 응답을 확인할 수 있습니다.

각 기록은 캐시를 사용해 13.625초와 11.624초였습니다. 이 한 쌍으로 일반적인 위치 정확도를 주장하지 않습니다. 제품의 세부 형태는 여전히 달라졌고 오른쪽에는 기존 작은 탁자와 침대의 앞뒤 관계가 모호해 가림을 추가 검토해야 합니다.

다음에는 같은 입력의 이전 방식을 재현하고, 반복 입력과 새 홀드아웃, 블라인드 사람 평가를 수행하겠습니다. Colab CUDA도 실제로 실행하겠습니다. 목표는 실제 입력에서 설득력 있는 배치 시각화입니다. 감사합니다.
